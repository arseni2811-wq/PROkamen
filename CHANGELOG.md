# Changelog

## 2026-09-02

### Добавлено

- Предварительная раскладка деталей и скинали по габаритам слэба с технологическим зазором 4 мм, визуальными продолжениями и проверкой физических размеров.
- Расширенная настройка обрабатываемых сторон: лицевая кромка, левый/правый торец и стороны изделия у стены.
- Высота скинали и включение её площади в расход выбранного камня.
- Сравнение до трёх материалов по агрегатам «Материал», «Работы» и «Итого».
- Безопасное прикрепление к публичной заявке одного эскиза или фото в PDF, DWG, PNG, JPG или WEBP до 15 МБ.

### Изменено

- Публичный интерфейс, API и PDF больше не раскрывают стоимость отдельных операций: клиент видит только стоимость материала, всех работ и общий итог.
- Подробные ставки и производственные строки сохранены только во внутреннем калькуляторе CRM.
- Логика монтажа и доставки не расширялась.

### Проверено

- Добавлены регрессионные тесты сторон обработки, площади скинали, раскладки длинной детали, публичной приватности цен и DWG-сигнатуры.

## 2026-09-01

### Добавлено

- Отдельные публичные сценарии подоконника (прямой, угловой, эркерный) и стола (прямоугольный, круглый, овальный) с собственной геометрией, изображениями и набором доступных услуг.
- Автоматическая длина скинали по тыльному периметру столешницы с возможностью перейти к ручной длине.
- Семь визуальных моделей передней кромки с отдельными реалистичными изображениями; выбор сохраняется в расчёте и PDF, а индивидуальные тарифы можно добавить позже.

### Изменено

- П-образная столешница получила более компактные стартовые пропорции и новое реалистичное изображение.
- Закреплённый краткий итог плавно скрывается при переходе к подробной смете и контактной форме.
- Убраны повторяющиеся информационные блоки под калькулятором; сокращён текст заявки.

### Исправлено

- Выбор подоконника больше не оставляет формы, изображения, вырезы и другие опции кухонной столешницы.
- Эркерный подоконник автоматически получает две стыковки, столы — кромку по полному периметру.
- Для П-образной столешницы учитываются две стыковки между тремя отдельными участками вместо трёх.
- Прямой раскрой столешниц и подоконников считается по одной длине и одной глубине каждой детали с учётом раскроя от края слэба; кромка учитывается только по лицевым длинам без боковых торцов.
- Деталь длиннее выбранного слэба автоматически делится на секции: на каждое продолжение добавляются поперечный раскрой по глубине, один стык и полировка по глубине, без увеличения видимой кромки.

### Проверено

- 66 модульных тестов, полный интеграционный сценарий, три эталонных ценовых сценария и визуальная браузерная проверка без ошибок консоли.
- Созданы помеченные тестовые записи `QA-CALC-V4-20260901`: публичный лид №3, заказы №21 и №22.

### Архитектурные решения

- Calculator update вынесен в отдельный endpoint; при нескольких items сервер возвращает `409`, не выполняя replace-all.
- Scope idempotency key — пара `(actor_id, key)`; одинаковый payload replay-ится, иной payload конфликтует.
- Новая версия сервера требует применения обязательных versioned migrations и не изменяет рабочую схему автоматически.
- Startup guard проверяет `orders.version` и idempotency table до legacy compatibility DDL, поэтому запуск немигрированной рабочей БД не выполняет скрытых schema/data writes.
- Зафиксированы границы публичного сайта, CRM, Express API и MySQL, а также правила актуализации постоянного контекста.
- Зафиксировано требование сохранять API-контракты и бизнес-логику при визуальных изменениях.
