# Калькулятор «ПРО Камень»

## Архитектура

Оба интерфейса передают только конфигурацию изделия. Единственный расчёт выполняет `backend/services/calculatorService.js` по опубликованной версии прайса из MySQL. Публичная проекция не содержит базовых USD-цен, закупки, резерва и внутренних коэффициентов.

Снимок schema v2 содержит курс, версию прайса, материал, формат, конфигурацию, строки и промежуточные/итоговые суммы. После сохранения заказа PDF использует снимок и не пересчитывает архивный заказ по текущему прайсу. Legacy-снимки поддерживаются отдельно.

## Безопасный rollout

1. Сделать резервную копию рабочей MySQL и проверить восстановление.

   Для локальной базы можно создать SQL-копию встроенным скриптом:

   ```bash
   cd backend
   node scripts/backup-database.js /absolute/path/prokamen-backup.sql
   ```
2. Для существующей базы один раз принять baseline согласно `CONTEXT.md`.
3. Применить последовательные миграции:

   ```bash
   cd backend
   ALLOW_SCHEMA_MIGRATIONS=1 npm run migrate
   ```

4. После миграции 005 импортировать метаданные существующего каталога:

   ```bash
   ALLOW_CATALOG_IMPORT=1 npm run import:calculator-catalog
   ```

   Импорт не придумывает закупочные цены и не копирует изображения. Материал с нулевой `base_price_usd_cents` не попадает в публичный каталог.
   Legacy-поле `price_per_m2` сохраняется для совместимости и не перезаписывается при повторном импорте.

5. В административной панели заполнить базовые цены USD, проверить рассчитанные BYN-значения, активность и публичную доступность материалов.
6. Сохранить курс/коэффициенты в черновик и опубликовать новую версию прайса.
7. Выполнить read-only integrity check и основные сценарии калькулятора/PDF.

## Начальные правила

- Форматы: Normal 3050×1440×20, Jumbo 3200×1600×20, Super Jumbo 3300×1650×20 и Custom.
- Автоматический расход: площадь деталей + процент отходов, деление на площадь слэба, округление вверх до 0,5.
- В публичном интерфейсе формат и толщина слэба определяются выбранным материалом; отдельного ручного выбора формата нет.
- Ручная полировка: площадь до 1,00 м² включительно использует малый тариф; свыше 1,00 м² — большой.
- Рекомендуемая цена: техническая сумма + резерв, но не ниже минимального заказа.
- Публичная цена: рекомендуемая цена × публичный коэффициент, затем округление вверх до заданного шага.
- Ручная скидка/надбавка применяется только к конечной цене КП менеджера.

## Формула автоматического пользовательского расчёта

Пользователь не вводит производственные метры и количество стыков. Для каждого изделия сервер выводит их из формы и размеров:

1. Площадь изделия:
   - прямая, Г- и П-форма: `S = Σ(длина участка × глубина участка) / 1 000 000`;
   - прямоугольный стол: `S = длина × ширина / 1 000 000`;
   - круглый стол: `S = π × (диаметр / 2)² / 1 000 000`;
   - овальный стол: `S = π × (длина / 2) × (ширина / 2) / 1 000 000`;
   - остров с радиусами: из прямоугольника вычитается для каждого угла
     `R² × (1 − π / 4)`;
   - бар с одним полукруглым торцом:
     `S = ((длина − глубина / 2) × глубина + π × (глубина / 2)² / 2) / 1 000 000`.
2. Площадь с технологическим отходом:
   `Sₒ = S × (1 + wasteBps / 10 000)`.
3. Расход камня:
   `slabs = ceil((Sₒ / площадь слэба) × 2) / 2`.
   Параллельно сервер строит предварительную раскладку прямоугольных деталей по слэбам с технологическим зазором 4 мм. Она проверяет, что глубина детали и высота скинали физически помещаются в выбранный формат, и показывает менеджеру/клиенту места продолжений. Коммерческий расход по-прежнему округляется по утверждённому правилу кратно 0,5.
4. Раскрой:
   - для столешниц и подоконников каждая прямоугольная деталь располагается от края слэба, поэтому учитывается одна длина и одна глубина: `Lstraight = Σ(длина + глубина) / 1 000`;
   - для острова и прямоугольного стола, у которых открыт весь внешний контур, используется полный периметр: `Lstraight = 2 × (длина + глубина) / 1 000`;
   - каждый радиусный угол заменяет `2R` прямого реза дугой `πR / 2`;
   - у бара прямой рез равен `2 × (длина − глубина / 2) + глубина`, а фигурный рез полукруглого торца — `π × глубина / 2`.
   Если длина отдельной детали превышает длину выбранного слэба, сервер автоматически делит её на секции:
   - `Nsections = ceil(длина детали / длина слэба)`;
   - `Nlength joints = Nsections − 1`;
   - дополнительный поперечный раскрой: `Lextra cut = Nlength joints × глубина / 1 000`;
   - полировка для стыковки: `Ljoint polish = Nlength joints × глубина / 1 000`.
   Эти метры прибавляются один раз на каждое место стыковки. Технологический поперечный рез не увеличивает длину видимой лицевой кромки.
5. Лицевая кромка:
   - у столешницы и подоконника учитывается только сумма лицевых длин всех участков; боковые торцы в автоматическую обработку не входят;
   - в сворачиваемом блоке «Уточнить обрабатываемые стороны» можно дополнительно отметить левый и/или правый торец: каждый выбранный торец добавляет соответствующую глубину ровно один раз;
   Для острова, бара и стола кромка автоматически считается по полному внешнему периметру, включая дуги. Периметр овального стола определяется приближением Рамануджана.
   В интерфейсе доступны семь визуальных профилей `Мод. 1–7`; выбранная модель сохраняется в заявке, снимке заказа и PDF. До загрузки индивидуальных расценок все модели используют действующий базовый тариф `edge_standard`, поэтому выбор формы кромки пока не меняет стоимость.
6. Стыки по форме:
   - столешница: прямая — 0, Г-образная — 1, П-образная — 2;
   - подоконник: прямой — 0, угловой — 1, эркерный — 2;
   - стол — без стыков в рамках одного полотна.
   К этому количеству добавляется `Nlength joints` для каждой детали длиннее слэба.
   При глубине до 700 мм применяется `joint_short`, свыше — `joint_long`.
7. Монтаж столешницы, подоконника и бортика считается по сумме длин участков. Монтаж острова и бара — по длине отдельного изделия. Вклейка подстольной мойки добавляется одной операцией. Эта логика сохранена без новых сценариев доставки и монтажа.
8. Скинали:
   - автоматическая длина равна сумме отмеченных сторон у стены: тыльной длины и, при выборе, левого/правого торца;
   - при ручном режиме используется введённая длина;
   - `Sскинали = длина скинали × высота / 1 000`, если длина задана в метрах, а высота — в миллиметрах;
   - площадь скинали добавляется к площади материала;
   - прямой раскрой скинали приближённо равен `длина + высота / 1 000`, так как панель раскраивается от краёв слэба.
9. Вырез мойки, варочной панели, отверстие под кран и дополнительные отверстия добавляются по визуальному выбору пользователя.

Интерфейс не показывает кухонные вырезы, бортики и скинали для подоконника и стола. Подоконник предлагает прямую, угловую и эркерную формы; стол — прямоугольную, круглую и овальную.

Денежная часть:

`материал BYN = материал USD × курс BYN/USD`;

`работы BYN = Σ(базовая ставка USD × автоматическое количество) × курс BYN/USD`;

`техническая сумма = материал + работы + внутренние доплаты`;

`рекомендуемая цена = max(техническая сумма × (1 + резерв), минимальный заказ)`;

`публичная цена «от» = округление вверх(рекомендуемая цена × публичный коэффициент)`.

USD хранится только как внутренняя база индексации и не выводится пользователю.

Публичный API, экран и клиентский PDF не возвращают и не показывают ставки или цены отдельных операций. Клиент видит только три денежные величины: «Материал», «Все работы» и «Итого от». Полная построчная калькуляция остаётся в CRM. В публичной форме можно приложить один эскиз или фотографию в PDF, DWG, PNG, JPG или WEBP до 15 МБ; файл сохраняется вместе с заявкой.

## Проверка

```bash
cd backend
npm test
npm run check:syntax
npm run test:migrations
npm run test:integration
npm run test:calculator-scenarios
```

`test:migrations` и `test:integration` создают базы со специальными тестовыми именами и удаляют их после завершения. Рабочую базу эти сценарии не меняют.
