# AGENTS.md

## Назначение

Веб-проект компании «ПРО Камень»: публичный информационный сайт и внутренняя CRM для учета клиентов, расчета стоимости, ведения заказов по этапам, работы с материалами, файлами и финансами заказа.

## Стек

- Frontend: HTML5, CSS, JavaScript ES modules; CRM использует обычный JavaScript и Tailwind CSS через CDN.
- Backend: Node.js, CommonJS, Express 5.
- Данные: MySQL (`mysql2`), JSON/CSV-файлы публичного сайта, `localStorage` для клиентского кэша и черновиков.
- Безопасность и сервисы: JWT, bcrypt, Zod, CORS, cookies, Multer, PDFKit, worker threads.

## Структура и точки входа

- `backend/server.js` — точка входа сервера, подключение API, раздача `public/`, проверка и дополнение схемы MySQL.
- `backend/db.js` — пул соединений MySQL из переменных окружения.
- `backend/routes/`, `backend/controllers/` — API-маршруты и бизнес-операции.
- `backend/middleware/` — JWT-аутентификация, роли и Zod-валидация.
- `backend/utils/`, `backend/workers/` — статусы заказов и генерация PDF.
- `backend/migrations/` — SQL-изменения схемы; не является полной схемой чистой БД.
- `public/index.html`, `public/js/main.js` — публичный сайт.
- `public/pages/` — страницы публичного сайта; `public/assets/` — JSON, CSV, изображения.
- `public/crm/crm/login.html`, `public/crm/crm/dashboard.html`, `public/crm/crm/js/api.js` — вход и основные точки CRM.
- `public/php/` — PHP-обработчики публичной части; Express намеренно не исполняет и не раздает этот каталог.

## Команды

Из корня проекта:

```bash
cd backend
npm ci
npm start
```

Сервер и сайт доступны на `http://localhost:3000`; для подключения MySQL нужны `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_DATABASE`. Поддерживаются также `JWT_SECRET`, `FRONTEND_ORIGIN`, `NODE_ENV`, `DEBUG_STATIC`.

Автоматический `npm test` не настроен. При запущенном сервере и подготовленной БД существует ручной интеграционный сценарий:

```bash
cd backend
node test_sprint1.js
```

## Ограничения работы

- Не изменять без явного запроса `.env`, учетные данные, `backend/init-users.js`, `public/php/config.php`, SQL-схему и миграции, API-контракты, аутентификацию/авторизацию, `package-lock.json` и пользовательские незакоммиченные изменения.
- При локальной задаче читать только необходимые файлы, а не весь проект.
- Не выполнять общий рефакторинг без явного запроса.
- Не обновлять зависимости без необходимости.
- При задачах по дизайну и оформлению не менять backend и бизнес-логику.
- Перед изменением существующей архитектуры сначала изучить `CONTEXT.md`.
- После существенных архитектурных изменений актуализировать `CONTEXT.md`.
- После выполнения задачи при необходимости обновлять `TODO.md`; значимые изменения фиксировать в `CHANGELOG.md`.

## Работа с интерфейсом

- Сохранять существующие API-контракты и визуальные соглашения проекта.
- Новые изображения хранить в подходящем существующем каталоге `public/assets/images/`; не создавать дубликаты ресурсов.
- Проверять относительные веб-пути к изображениям и другим ресурсам.
- Учитывать запуск и работу проекта на macOS и Windows.
- Не добавлять абсолютные пути вида `/Users/...` или `C:\Users\...`.
